ANDROID HOST

RxD on the phone.

Arxd is an Android Agent workspace: Expo 58 + Pi-durable + an embedded ARM64 rxd. Conversations, files, skills, MCP and optional on-device models share one device.

Build guide ↗ Design ↗

ARXD / 0.1.0 / ANDROID

A workspace, not a wrapper.

Native screens handle interaction, Pi-durable runs the Agent loop, and RxD performs analysis. Keeping the layers separate lets one real query finish on the device.

On-device models

Download the pinned Qwen3.5-2B Q4_K_M (1.28 GB) or import a GGUF. llama.rn runs text inference on CPU, up to 8k context and a 1,024-token reply. Thinking is opt-in. Models are not embedded in the APK; imports are SHA-256 bound and must pass a real-engine probe.

Model connections

OpenAI Completions/Responses, Anthropic Messages and Google Generative AI through Pi AI. Named connections, model settings and device credentials; credentials use Android Keystore/SecureStore. Local HTTP endpoints are supported with an explicit unencrypted warning.

Real analysis

The embedded ARM64 rxd covers JS, ASAR, HTML, APK/DEX, JVM, .NET, WASM, EVM, PYC and Kuna. rxd_file_outline is a bounded JS fast path; other formats use $ARXD_RXD in the shell.

Durable workspace

Pi-durable handles conversations, tool rounds and persistence. SQLite keeps history, archives, attachments and reports. Deleting a conversation does not delete files from the library.

Files and skills

Browse, edit, copy, share and attach files. Import SKILL.md, a directory or a workspace skill; imports are disabled by default. The Agent loads admitted skills on demand.

MCP and processes

Save stdio launch definitions or HTTP(S) endpoints, connect and discover tools. Long-running process instances are visible and stopped explicitly. Plain HTTP is loopback-only on Android.

Three layers, clear boundaries.

LayerResponsibility
Arxd hostNative screens, theme, document picker, sharing and process management. Not a WebView.
Pi-durableConversations, tool rounds, context compaction, persistence and recovery.
RxDParsing and decompilation in shared Rust backends; identities, budgets and output contracts unchanged.

An on-device model is optional and never changes analysis identity. The same file queried from the CLI or Arxd gets the same input-hash/byte-range IDs.

Capability and limits.

Arxd is an Android host, not a complete product guarantee. These limits are part of the design.

Android ARM64 only

Build from source following apps/arxd/README.md. Device evidence and host checks are recorded separately; there is no published APK yet.

The on-device model is not a sandbox

The 2B CPU path differs in capability and latency from cloud models. The shell tool does not provide network isolation; untrusted input should still be isolated outside the device.

Imports are explicit

Skill and model imports are disabled by default; enable only workflows you trust. Model files are not embedded in the APK, and imports must pass hash, template and tool-parser probes.

Build and verify.

Arxd lives in the same repository as RxD and needs the Android SDK/NDK. Model files, APKs and device evidence are not committed. See the README for exact prerequisites and verification boundaries.

git submodule update --init third_party/kuna
cd apps/arxd
npm ci --ignore-scripts
npm run build:rxd
python3 scripts/build-preload.py
npx expo prebuild --platform android --no-install
cd android && ./gradlew :app:assembleRelease --max-workers=2 -PreactNativeArchitectures=arm64-v8a
