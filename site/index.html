START

Build once. Query anything.

Release binaries are published from the Build RxD workflow. From source, initialize the Kuna path dependency and build the default all-feature profile.

git submodule update --init third_party/kuna
cargo build --release
target/release/rxd --version
target/release/rxd skill install -a pi

Reduced builds are explicit: --no-default-features --features backend-js. See the installation guide.

WHY RXD

Fast primitives, not one heavy call.

Content-bound identity

Every ID binds the input hash and a real byte range. Extraction returns original bytes, never a reconstruction of the address.

Agent-first output

Stable JSONL envelopes: header, records and summary. Detail is a closed per-record schema. Raw source stays byte-exact.

No execution

Parsers read fixed buffers. Inputs and recovered modules are never executed; budgets and atomic failures are explicit.

Honest degradation

When a decompiler cannot recover a unit, the full original IL/bytecode/instructions and a reason remain. Partial guesses are not returned.

PROVENANCE

Where the backends come from.

Each backend names its upstream engine or states that it is RxD-owned. Versions and licenses stay auditable; the boundary of every engine stays visible.

Exact versions, licenses and local patches live in NOTICE and the backend design docs. Upstream engines are pinned; RxD-owned backends keep the same output identity and degradation contract.
