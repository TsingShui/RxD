# Published and obfuscated corpus

Ordinary E2E uses saved JS files and independent Acorn expectations; it does not access
the network, install npm dependencies or execute sample code. Handwritten small inputs
still isolate boundary behavior. This corpus covers real published code and transforms
produced by actual tools.

## Pinned samples

| Sample | Origin / transform | Verification target |
| --- | --- | --- |
| jQuery 4.0.0 | npm package `dist/jquery.min.js` | Selector error string → actual function |
| Lodash 4.18.1 | npm package `lodash.min.js` | Shared error string → outer wrapper, demonstrating context-range limits |
| Vue 3.5.43 | npm package `dist/vue.global.prod.js` | Runtime error URL → error handler |
| application-terser | Terser 5.51.2 minification and top-level renaming | Minified API-request closure |
| application-renamed-escaped | javascript-obfuscator 5.9.0 renaming and Unicode escapes | Decoded literal matching where raw-text search may miss |
| application-flattened-string-array | Control-flow transform, dead code and string array | Strings live in an array factory; a hit is not assumed to be the original business function |
| application-rc4 | RC4 string encoding | Plaintext query returns zero hits; structural location/extraction still works |

The first three are real production files from public open-source libraries, not full
business-site bundles. The last four come from this project's `application.js` login,
cache, error-handling and nested-closure scenario and are not labeled as live code.

`manifest.json` records exact versions, file SHA-256, npm tarball origin, license,
generator, Node version, seed and all obfuscation parameters. Versions and npm
integrity are pinned in `package-lock.json`; third-party licenses are in `licenses/`.
Published files keep their original bytes and copyright headers.

## Independent expectations and E2E

Acorn 8.19.0 parses each input independently and emits canonical structure summaries,
string matches and representative source ranges. Its UTF-16 character indices are
converted to original-file UTF-8 byte offsets. Expectations never come from rxd/Oxc.

`tests/cli.rs` checks every structure's kind, range, parent/child relation, depth, name
and flags through the real CLI, verifies string hit positions/owning entity, and then
exercises the full `get/locate/get --json` flow. Encrypted cases explicitly verify that
zero hits is a successful result; the static CLI is not required to decrypt or recover
runtime call relationships.

`strings-expectations.json` comes from `generate-strings.mjs`: pinned Acorn
independently enumerates every string literal/cooked template part in jQuery,
the plain-table and RC4 artifacts. E2E checks occurrence counts and hashes of
ordered UTF-8 range/value tuples, including duplicates and empty strings. It
validates default enumeration, not decrypted values or inferred call relations.

`refs-expectations.json` stores independent lexical queries for all seven samples:
Acorn selects single-parameter functions/arrows with exactly one return/throw or an
expression body and no nested binding/assignment, then derives every read of that
parameter directly from the AST, excluding literals and non-computed property keys.
This restricted oracle does not claim general scope analysis; shadowing, closures,
writes and dynamic boundaries are covered by handwritten CLI scenarios. Expectations
include generator hash, Acorn version, input SHA-256, raw ranges and flags, never rxd
output, and never decrypt obfuscated strings.

Plain literal-table lookups are proven separately when a query asks for them:
`find --resolve-static` and `calls/members --resolve-static` resolve
`application-flattened-string-array` (plain table, solved rotation) and every
`literal_table_decoder_*` test pins that behavior. `application-rc4` stays
unresolved both by default and with `--resolve-static`: RC4 is unsupported, not
recognized through a stored sample/template. Direct standard `atob` tables have
separate handwritten correctness/Latin-1 and mutation regressions; no corpus
plaintext expectations are changed.

```sh
cargo test --test cli refs_
cargo test --test cli published_and_obfuscated_corpus
cargo test --release --test cli
python3 benches/cli.py
python3 benches/cli.py --case application-rc4
```

`definitions-expectations.json` is generated by independent `generate-definitions.mjs`:
it selects a variable name declared exactly once in the whole file, avoiding a general
scope oracle, and records canonical identifier, single declarator, declaration kind and
initializer UTF-8 ranges. Among initialized 32–2048-byte declarators it picks the sample
with the largest containing-structure/declaration ratio to demonstrate binding
extraction reduction; this is not an average-benefit estimate. E2E verifies raw bytes,
metadata and identity through symbols → get symbol ID; destructuring, parameters,
imports and redeclarations are covered by handwritten scenarios. Sample code is never
executed.

`contexts-expectations.json` is generated by independent `generate-contexts.mjs` with
Acorn, reusing anchors from existing literals and the restricted refs oracle to store
local syntactic ancestor ranges and direct parent fragments; function/class/method
boundaries reset context. E2E cross-checks find/locate/refs → get identity, parent
relations and raw bytes across all seven inputs; class fields, object properties, writes
and boundary recovery use handwritten scenarios. Inputs are parsed fully and never
executed.

The independent Babel corpus for JSX/TS/TSX lives in `typed/`: real published
declaration files parsed with pinned @babel/parser 7.29.9 and @babel/types 7.29.8, plus
explicitly handwritten JSX/TSX browser sources. `generate-typed.mjs` uses the pinned
parser to emit structure hashes, search positions, restricted parameter references,
declaration and local-context ranges; samples are never executed. Origin tarballs, npm
integrity, licenses, input hashes and generator hashes are retained. TypeScript
parameter identifier positions use original lexical tokens excluding annotations;
type checking and full scope solving are not promised by this oracle.

`modules-expectations.json` is generated by `generate-modules.mjs` from the pinned
YAML VSIX in `zip/`. Acorn independently finds unique function-scope registry
bindings and literal factories connected to module/module.exports/self-runtime
invocations, including methods and arrays. Its 45 retained modules across three
registries have independent IDs, UTF-8 ranges and payload hashes; E2E compares
all of them and slices representative original units. This restricted oracle
excludes ambiguous declarations; it is not generated from rxd/Oxc results.
The VSIX provenance and embedded license/notices remain in `zip/README.md`.

## Regeneration

Only corpus updates need Node 22+ and npm:

```sh
cd tests/corpus
npm ci --ignore-scripts --no-audit --no-fund
npm run generate
node generate-refs.mjs
node generate-definitions.mjs
node generate-contexts.mjs
node generate-typed.mjs
node generate-modules.mjs
node generate-strings.mjs
```

Review generated files, independent expectations and licenses, then run E2E. Never
update expectations from rxd output, download floating versions or fetch pages during a
test. The obfuscation seed is fixed at 20261010; changing tools, parameters or Node
version requires rechecking hashes and results.

Upstream documentation: [Terser](https://terser.org/docs/cli-usage/),
[javascript-obfuscator](https://github.com/javascript-obfuscator/javascript-obfuscator),
[Acorn](https://github.com/acornjs/acorn).

## JVM bytecode corpus

Pinned Gson/Rhino JARs, licenses and independent javap expectations are in

executes their code.

## EVM pinned compiler corpus

`evm/` retains solc 0.8.26 authored viaIR/legacy and OpenZeppelin 5.1.0 ERC20 runtime,
independent raw-instruction/selector expectations, package integrity, source/runtime
hashes, generators and licenses. It is an offline compiler corpus, not a chain download
or execution result; see [EVM corpus README](evm/README.md).
